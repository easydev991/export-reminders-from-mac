## Context

Новый greenfield-проект: Swift CLI-инструмент для выгрузки напоминаний из Apple Reminders. Проект создаётся как SPM-пакет (`executable`), целевая платформа — macOS 14+. Существующий код отсутствует, есть только fallback-скрипты в `scripts/` (JXA и AppleScript). План проекта описан в `PLAN.md`.

**Ограничения:**
- Требуется доступ к системной БД Reminders через EventKit
- Требуется TCC-разрешение (`com.apple.security.personal-information.reminders`)
- CLI-бинарник должен работать без установленного Xcode (только swift runtime)
- Проект использует русский язык для документации и тестовых описаний

## Goals / Non-Goals

**Goals:**
- Чтение всех напоминаний и списков из Apple Reminders через EventKit напрямую (без IPC к приложению)
- Экспорт в два формата: JSON (канонический, полное сохранение данных) и CSV (универсальный табличный, для импорта в сторонние приложения: TickTick, Microsoft To Do, Notion)
- Фильтрация по имени списка и статусу выполнения через аргументы CLI
- Скорость: выгрузка 1 000+ напоминаний < 5 секунд
- Полное покрытие unit-тестами всех модулей по TDD
- Тестирование на Swift Testing (не XCTest)

**Non-Goals:**
- GUI-интерфейс
- Экспорт в другие форматы (XML, Plist, PDF, ICS, Markdown и т.д.) — Markdown и ICS исключены осознанно: Markdown — человеко-читаемый формат, не для импорта; ICS (iCalendar) не поддерживается Android-приложениями для задач (VTODO не импортируется в Google Tasks, Samsung Reminders)
- Синхронизация с внешними сервисами (облака, календари)
- Редактирование/создание напоминаний
- Поддержка iOS/iPadOS/watchOS
- Поддержка macOS < 14

## Decisions

### 1. SPM-структура: модульная, но внутри одного executable-таргета

**Выбор**: Единый executable-таргет `ExportReminders` с внутренними подпапками (`Models/`, `Services/`, `Exporters/`), а не отдельные library-таргеты.

**Обоснование**: Проект небольшой (10-15 файлов). Выделение в отдельные модули усложнит тестирование и сборку без ощутимой выгоды. При росте проекта можно выделить библиотеки.

**Альтернативы**: Несколько SPM-таргетов (`ExportRemindersCore`, `ExportRemindersCLI`). Отвергнуто как over-engineering для текущего масштаба.

### 2. EventKit напрямую, без абстракций над Apple-API

**Выбор**: Сервис `EventKitReminderService` напрямую вызывает `EKEventStore`. Для тестов используется протокол `ReminderServiceProtocol` с мок-реализацией.

**Обоснование**: EventKit — единственный источник данных. Абстракция на уровне протокола даёт тестируемость без усложнения production-кода.

### 3. swift-argument-parser для CLI

**Выбор**: Пакет `swift-argument-parser` от Apple. Единственная внешняя зависимость.

**Обоснование**: Де-факто стандарт для Swift CLI. Автоматическая генерация `--help`, валидация аргументов, поддержка `async`.

**Альтернативы**: Ручной парсинг `CommandLine.arguments` — не даёт автодокументирования и проверки типов. Vapor Console — слишком тяжёлый.

### 4. Swift Testing вместо XCTest

**Выбор**: Использовать `import Testing` для всех unit-тестов.

**Обоснование**: Современный фреймворк, параллельное выполнение по умолчанию, читаемые макросы `#expect`/`#require`, русские описания в `@Test`. Проект новый — нет легаси XCTest.

**Альтернативы**: XCTest — больше boilerplate, нет встроенной параметризации, сложнее параллельное выполнение.

### 5. Протоколы для контрактов экспорта и сервиса

**Выбор**: `ReminderExporterProtocol` (один метод `export`) и `ReminderServiceProtocol` (два метода: `fetchAllReminders`, `fetchAllLists`).

**Обоснование**: Позволяет тестировать CLI с мок-сервисом и мок-экспортёром. Новые форматы экспорта добавляются реализацией протокола без изменения CLI-кода.

### 6. Swift Concurrency (async/await) для EventKit-вызовов

**Выбор**: Использовать `async/await` с `withCheckedContinuation` для callback-based EventKit API.

**Обоснование**: EventKit использует completion handlers. Оборачивание в `async` даёт линейный код, совместимый с `swift-argument-parser` (поддерживает `async run()`).

### 7. Приоритет: сразу использовать Swift Testing

**Выбор**: Все тесты с первого дня пишутся на Swift Testing (`import Testing`). XCTest не используется.

**Обоснование**: Указано пользователем. Конвенции: русские описания в `@Test`, `#expect`/`#require`, мок-клиенты для интеграции.

## Risks / Trade-offs

- **[R] TCC-диалог не появляется для CLI-бинарника** → Mitigation: добавить entitlements в `Package.swift` через `unsafeFlags` или собрать как минимальное приложение с `LSUIElement=true`
- **[R] EventKit возвращает пустой список для iCloud-напоминаний без авторизации** → Mitigation: явная проверка статуса доступа с понятным сообщением об ошибке
- **[R] Даты из EventKit используют компоненты (DateComponents), а не Date** → Mitigation: преобразование `dueDateComponents` → `Date` при маппинге, документирование потери точности timezone
- **[R] CSV-колонки могут не совпадать с ожидаемым форматом конкретного Android-приложения** → Mitigation: CSV использует универсальные англоязычные названия колонок; JSON — канонический формат для последующей конвертации. Отдельной задачей можно добавить `--csv-preset <app>` с пресетами под конкретные приложения
- **[R] Единственная внешняя зависимость (`swift-argument-parser`) может блокировать обновление Swift** → Mitigation: используется стабильная версия 1.2.0, можно заменить на ручной парсинг при необходимости
